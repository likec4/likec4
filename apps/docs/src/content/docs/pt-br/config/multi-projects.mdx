Às vezes, você pode querer dividir seu modelo LikeC4 em vários modelos, com base em domínios, equipes ou qualquer outro critério.

Você pode fazer isso criando vários projetos no seu workspace e vinculando-os entre si.  
Também pode usar esse recurso para compartilhar seu modelo com outras equipes ou projetos.

Crie arquivos `likec4.config.json` nas pastas que você deseja transformar em projetos:

<FileTree>
- cloud
  - **likec4.config.json**
  - service1.c4
  - service2.c4
  - ...
- externals
  - **likec4.config.json**
  - amazon.c4
  - ...
</FileTree>

O LikeC4 encontra os projetos percorrendo o workspace (a pasta aberta no editor ou o caminho passado à CLI) em busca de [arquivos de configuração](/pt-br/config/#arquivo-de-configuração), ignorando pastas como `node_modules` e `.git`.  
Cada arquivo de configuração define um projeto na sua pasta.  
Um arquivo-fonte pertence ao projeto com a pasta mais próxima.  
Arquivos fora de qualquer pasta de projeto, e não incluídos por nenhum projeto, pertencem ao projeto `default`.

Os projetos podem ser aninhados.  
Nesse caso, os arquivos do projeto aninhado não fazem parte do projeto pai.

<FileTree>
- cloud
  - likec4.config.json
  - service1.c4
  - service2.c4
  - nested
    - likec4.config.json
    - service3.c4 // fará parte do projeto 'nested', não do projeto 'cloud'
</FileTree>

## Importar elementos

Você pode importar elementos de outros projetos usando a palavra-chave `import`.

```likec4
import { serviceA } from 'projectA'

model {
  serviceB = service {
    -> serviceA.api 'calls serviceA'
  }
}
```

<Aside type='caution' title="Limitações">
No momento, aplicam-se as seguintes limitações:
- Os projetos referenciados devem estar carregados no mesmo workspace
- Apenas elementos de **model** no nível superior podem ser importados
</Aside>

## Compartilhar especificação

Você pode compartilhar arquivos de especificação (ou qualquer outra fonte LikeC4) entre vários projetos usando a opção de configuração `include`.

### Usando caminhos de inclusão

Adicione uma configuração `include` ao seu projeto para incluir arquivos de diretórios fora da pasta do projeto:

<FileTree>
- shared
  - specs.c4
  - common-styles.c4
- cloud
  - likec4.config.json
  - services.c4
  - ...
- externals
  - likec4.config.json
  - amazon.c4
  - ...
</FileTree>

Os projetos `cloud` e `externals` podem incluir a especificação compartilhada:

```json title="cloud/likec4.config.json"
{
  "$schema": "https://likec4.dev/schemas/config.json",
  "name": "cloud",
  "include": {
    "paths": ["../shared"]
  }
}
```

```json title="externals/likec4.config.json"
{
  "$schema": "https://likec4.dev/schemas/config.json",
  "name": "externals",
  "include": {
    "paths": ["../shared"]
  }
}
```

Os caminhos são relativos à pasta do projeto.  
Para `maxDepth`, `fileThreshold` e as regras dos caminhos, veja [Incluir diretórios adicionais](/pt-br/config/#incluir-diretórios-adicionais).

### Usando links simbólicos (alternativa)

Como alternativa, você pode usar links simbólicos para compartilhar arquivos:

<FileTree>
- shared
  - specs.c4
- cloud
  - specs.c4 // -> ../shared/specs.c4
  - likec4.config.json
  - ...
- externals
  - specs.c4 // -> ../shared/specs.c4
  - likec4.config.json
  - ...
</FileTree>

<Aside type='note'>
Em geral, a configuração `include` é preferível a links simbólicos, pois é mais portável e mais fácil de gerenciar.
</Aside>
