As visões de deployment permitem visualizar o modelo de deployment usando a mesma abordagem das [visões do modelo](/pt-br/dsl/views/predicates) — predicados.

## Definição da visão

```likec4 {17-23}
deployment {
  environment prod {
    zone eu {
      zone zone1 {
        instanceOf frontend.ui
        instanceOf backend.api
      }
      zone zone2 {
        instanceOf frontend.ui
        instanceOf backend.api
      }
      instanceOf database
    }    
  }
}
views {
  deployment view index {
    title 'Production Deployment'
    link https://likec4.dev

    include prod.**
    // ...
  }
}
```

## Predicados da visão

As visões de deployment são baseadas nos mesmos [predicados](/pt-br/dsl/views/predicates) das visões do modelo.  
Porém, elas fazem referência a nós e instâncias de deployment.

<Aside type='caution' title='Limitações'>
  As visões de deployment diferem das visões do modelo:

  - Expressões `with` em elementos suportam apenas `navigateTo`. As demais propriedades são ignoradas, e um `with` de elemento sem `navigateTo` não inclui nada. Use [regras `style`](/pt-br/dsl/views/styles#predicados-de-estilo) para alterar a aparência.
  - Estilos compartilhados do bloco `views`, estilos globais e grupos globais de predicados não são suportados.
  - O navegador de relacionamentos e o popup de detalhes de relacionamentos funcionam com o modelo lógico.
    O navegador de relacionamentos está disponível para instâncias implantadas e mostra os relacionamentos do elemento lógico;
    relacionamentos definidos no modelo de deployment não aparecem no popup de detalhes de relacionamentos.

  ```likec4
  deployment view prod {
    include *                                   // funciona
    include * where tag is #next                // funciona (veja Filtragem abaixo)
    include server with {
      navigateTo server_deployment              // funciona (veja Navegação abaixo)
    }
    include server with { color red }           // ignorado, apenas navigateTo é suportado
    style server { color red }                  // funciona

    include * -> *                              // funciona
    include * -> * where source.tag is #next    // funciona (veja Filtragem abaixo)
    include * -> * with { color red }           // funciona

    global style applications                   // não suportado
  }
  ```
</Aside>

### Navegação

Use `navigateTo` em uma expressão `with` de um elemento para abrir outra visão a partir de um nó ou de uma instância de deployment:

```likec4
views {
  deployment view prod {
    include server with {
      navigateTo server_deployment
    }
  }

  deployment view server_deployment {
    include server.*
  }
}
```

O destino de `navigateTo` deve ser uma visão existente.

### Filtragem

A filtragem em visões de deployment segue os mesmos princípios das visões normais, mas considera nós de deployment, relacionamentos, tags e metadados definidos no modelo de deployment.
Quando uma condição sobre um elemento é verificada, aplicam-se as seguintes regras:
- para instâncias de deployment, as tags são combinadas entre as definidas no modelo e as definidas no modelo de deployment;
- para um filho de uma instância de deployment, são usadas as tags definidas no filho no modelo;
- para um nó de deployment, são usadas as tags definidas no modelo de deployment;
- para instâncias de deployment, é usado o tipo do elemento do modelo;
- para um filho de uma instância de deployment, é usado o tipo desse filho;
- para um nó de deployment, é usado o tipo desse nó de deployment;
- para instâncias de deployment, os metadados definidos no modelo de deployment substituem os metadados do elemento do modelo;
- para endpoints de relacionamentos, `source.metadata.*` e `target.metadata.*` seguem as mesmas regras de metadados das instâncias implantadas;
- para nós de deployment, são usados os metadados definidos no modelo de deployment;
- tags não são herdadas de nós ou elementos pais.

```likec4
specification {
  element system
  element component
  deploymentNode environment
  deploymentNode zone
  tag next
  tag alpha
  tag beta
  tag gamma
  tag sigma
  tag delta
}
model {
  cloud = system {
    frontend = component {
      #next
      -> backend "rel1"
    }
    backend = component {
      #next
      -> db "rel2"
    }
    db = component
  }
}
deployment {
  environment prod { // Resulting tags: #alpha
    #alpha
    zone eu { // Resulting tags: #beta
      #beta
      instanceOf cloud.frontend { // Resulting tags: #next, #gamma
          #gamma
      }
      instanceOf cloud.backend { // Resulting tags: #next, #sigma
          #sigma
      }
      eu -> prod.db "rel3"
    }
    instanceOf cloud.db { // Resulting tags: #delta
      #delta
    }
  }
}
views {
  deployment view some {
    include prod.eu.frontend -> prod.eu.backend
      where source.tag is #next // includes relation "rel1"
    include prod.eu.frontend -> prod.eu.backend
      where source.tag is #gamma // includes relation "rel1"
    include prod.eu -> prod.db
      where source.tag is #beta // includes relation "rel3"
    include prod.eu -> prod.db
      where source.tag is #sigma // does not include any relations
    include prod.eu.* -> prod.db
      where source.tag is #sigma // includes relation "rel2"
  }
}
```

Predicados de metadados também podem ser usados com `include` e `exclude`:

```likec4
deployment {
  environment prod {
    instanceOf backend {
      metadata {
        zone 'public'
      }
    }
    instanceOf database {
      metadata {
        zone 'restricted'
      }
    }
  }
}

views {
  deployment view prod {
    include * -> *
    exclude * -> *
      where target.metadata.zone is "restricted"
  }
}
```

### Grupos

Use `group` para desenhar um contorno em volta de nós ou instâncias de deployment, sem alterar o modelo de deployment:

```likec4
deployment view production {
  group 'European zones' {
    color amber
    border solid
    opacity 20%

    include prod.eu.zone1, prod.eu.zone2
  }
}
```

Grupos podem ser anônimos ou aninhados, e podem conter predicados `include` e `exclude` de deployment.
Eles seguem as mesmas [regras de ordenação dos grupos de elementos](/pt-br/dsl/views/predicates#grupos).
Diferentemente dos grupos de elementos, os grupos de deployment são inseridos dentro do pai de deployment visível que compartilham,
incluindo ancestrais adicionados por `includeAncestors true`:

```likec4
deployment view production {
  include prod
  group 'Layer 2' {
    include prod.app1, prod.app2
  }
  group 'Layer 3' {
    include prod.api
  }
}
```

Aqui, os dois grupos ficam dentro de `prod`, e as instâncias selecionadas ficam dentro de seus grupos.
Os membros devem compartilhar o mesmo pai de deployment. Selecionar nós com pais diferentes é reportado como
erro, mesmo que esses pais não estejam visíveis ou compartilhem um ancestral comum. Nesse caso, use grupos separados
dentro de cada contêiner de deployment. Isso também se aplica a endpoints de relacionamentos e a seleções dentro de grupos aninhados.
Se um pai e seus descendentes forem selecionados no mesmo grupo, o grupo envolve o pai e preserva
sua hierarquia de deployment; o pai é considerado o membro ao verificar a exigência de pai compartilhado.

Grupos de predicados e estilos compartilhados não são suportados dentro de grupos de deployment.

### Incluir ancestrais

Às vezes, é útil visualizar exatamente como os elementos estão implantados. Nesse caso, você pode usar
o atributo `includeAncestors` em uma visão de deployment.

O objetivo desse atributo é forçar a exibição de todos os ancestrais dos elementos que já estão visíveis no diagrama final.  
Ele não afeta os relacionamentos visíveis. Trata-se apenas de uma preferência de representação que permite visualizar como cada elemento relevante está implantado.

```likec4
specification {
  element service

  deploymentNode hypervisor {
    style {
      color green
    }
  }
  deploymentNode vm {
    style {
      color red
    }
  }
  deploymentNode app_server {
    style {
      color sky
    }
  }
}

model {
  svc1 = service
  svc2 = service

  svc1 -> svc2
}

deployment {
  hyp1 = hypervisor {
    vm = vm {
      tomcat1 = app_server "tomcat" {
        instanceOf svc1
      }
    }
  }
  hyp2 = hypervisor {
    vm = vm {
      tomcat2 = app_server "tomcat" {
        instanceOf svc2
      }
    }
  }
}

views {
  deployment view ancestors_test {
    includeAncestors true

    include hyp1.vm.tomcat1.svc1
    include hyp2.vm.tomcat2.svc2
  }
}
```
