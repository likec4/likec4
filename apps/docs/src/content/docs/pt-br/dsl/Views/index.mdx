O LikeC4 é baseado em modelos. Uma visão é uma projeção do modelo: ela escolhe elementos e relacionamentos do modelo e os renderiza como um diagrama.
Quando o modelo muda, todas as visões que mostram a parte alterada são atualizadas.

O LikeC4 não impõe regras específicas, como um número rígido de níveis ou o que deve ser incluído — isso depende totalmente de você e do seu contexto.

## Tipos de visões

| Tipo                | Palavra-chave     | Mostra                                                                                  |
| :------------------ | :---------------- | :-------------------------------------------------------------------------------------- |
| Visão de elementos  | `view`            | Elementos e relacionamentos do modelo, escolhidos com [predicados](/pt-br/dsl/views/predicates/) |
| Visão dinâmica      | `dynamic view`    | Um cenário como passos ordenados entre elementos, como diagrama ou diagrama de sequência ([visões dinâmicas](/pt-br/dsl/views/dynamic/)) |
| Visão de deployment | `deployment view` | Nós de deployment e as instâncias implantadas neles ([visões de deployment](/pt-br/dsl/deployment/views/)) |

Esta página cobre o que todas as visões têm em comum. As próximas páginas explicam:

- [Predicados](/pt-br/dsl/views/predicates/) - o que uma visão de elementos mostra
- [Estilos](/pt-br/dsl/views/styles/) - a aparência dos elementos em uma visão e como compartilhar estilos entre visões
- [Visões dinâmicas](/pt-br/dsl/views/dynamic/) - cenários como passos, em diagrama ou sequência
- [Layout](/pt-br/dsl/views/layout/) - direção, espaçamento, roteamento das conexões, restrições de rank e os modos Diagram/Graph
- [Notações](/pt-br/dsl/views/notations/) - a legenda de uma visão
- [Organizar](/pt-br/dsl/views/organize/) - pastas e ordem das visões

## Definição de visão

As visões são definidas na seção `views`.
Elas podem ter nome (que deve ser único) ou não ter nome (não podem ser referenciadas, mas ainda podem ser exportadas):

```likec4
views {
  // with name
  view index {
  }
  // unnamed
  view {
  }
}
```

O nome da visão é usado como nome do arquivo de imagem durante a exportação e como parte da URL ao compartilhar, portanto é recomendável definir um.

<Aside title="Visão padrão">
  `index` é uma visão especial e é renderizada por padrão quando nenhum nome de visão é especificado.
  Se ela não estiver definida, será gerada e incluirá os elementos de nível superior.
</Aside>

### Propriedades da visão

As visões podem ter `title`, `description`, `tags`, `links`, [`routing`](/pt-br/dsl/views/layout/#roteamento-das-conexões) e [`order`](/pt-br/dsl/views/organize/#ordenar-visões):

```likec4
views {

  view epic12 {
    #next, #epic-12
    title "Cloud System - Changes in Epic-12"

    // Description can be Markdown with triple quotes
    description """
      This diagram shows the **high-level**
      components and interactions.
    """

    link https://my.jira/epic/12 'Epic-12'

    // Desenha relacionamentos com segmentos em ângulo reto
    routing ortho
  }

}
```

As propriedades devem ser definidas antes de qualquer [predicado](/pt-br/dsl/views/predicates/).

## Visões com escopo

Uma visão pode ser definida para um elemento específico (`view of ...`).
Nesse caso, a visão herdará o [escopo](/pt-br/dsl/references#escopo) desse elemento:

:::note
Você aprenderá sobre `include` e `exclude` na seção de [predicados](/pt-br/dsl/views/predicates/).
:::

```likec4
views {

  view {
    include api // ⛔️ Error: 'api' is not found
  }

  view of cloud.backend {
    include api // ✅ This is OK, resolves to 'cloud.backend.api'
  }

  view of legacy {
    include api // ✅ This is OK, resolves to 'legacy.api'
  }

}
```

Além disso, uma visão com escopo se torna a visão padrão do elemento:

```likec4
views {

  view {
    // on click navigates to 'view1',
    // because it is default for 'cloud.backend'
    include cloud.backend
  }

  view view1 of cloud.backend {
    include *
  }

}
```

Você pode definir várias visões para o mesmo elemento; a visão padrão é determinada pela ordem em que elas aparecem.

## Estender visões

Visões podem ser estendidas para evitar duplicação, criar uma "baseline" ou, por exemplo, "slides" para uma apresentação:

```likec4
views {

  view view1 {
    include *
  }

  view view2 extends view1 {
    title 'Same as View1, but with more details'

    style * {
      color muted
    }

    include some.backend
  }

  // cascade inheritance
  view view3 extends view2 {
    title 'Same as View2, but with more details'

    include * -> some.backend
  }

}
```

Os predicados e as regras de estilo das visões estendidas são aplicados depois dos definidos nas visões ancestrais.

Uma visão estendida também herda o escopo:

```likec4
views {

  view view1 of cloud.backend {
    title 'Backend components'
  }

  view view2 extends view1 {
    include api // ✅ This is OK, references 'cloud.backend.api'
  }

}
```
