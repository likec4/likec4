O LikeC4 pode **exportar** visões para [Draw.io](https://draw.io) (`.drawio`) para editar diagramas no Draw.io ou reutilizá-los em ferramentas compatíveis.

**CLI:** `likec4 export drawio` — consulte [CLI — Exportar para Draw.io](/pt-br/tooling/cli/#exportar-para-drawio).

Esta página explica o mapeamento na exportação, os perfis de exportação, a reexportação com blocos de comentários e as limitações.

:::note[Importação]
A importação a partir do Draw.io não é suportada: a CLI, o editor e o Playground apenas exportam.
O LikeC4 continua sendo a fonte da verdade; Draw.io é um formato de intercâmbio.

O pacote `@likec4/generators` possui conversores de baixo nível, `parseDrawioToLikeC4` e `parseDrawioToLikeC4Multi`,
que transformam um arquivo `.drawio` em código-fonte LikeC4 com os [blocos de comentários de intercâmbio](#reexportação-usando-blocos-de-comentários),
mas nenhum fluxo de importação é construído sobre eles.
:::

## Exportação (LikeC4 → Draw.io)

Por padrão, é criado um arquivo `.drawio` por visão (a visão ocupa uma aba de diagrama no arquivo).
Utilize `--all-in-one` na CLI para gravar todas as visões como abas de um único arquivo `.drawio`.

### Perfis de exportação

A exportação oferece dois perfis:

| Perfil   | Descrição |
| --------- | ----------- |
| `default` | Intercâmbio bidirecional padrão: layout, traços, pontos intermediários e atributos de estilo existentes (consulte [Mapeamento para Draw.io](#mapeamento-para-drawio)). |
| `leanix`  | Adiciona **metadados gerenciados pela integração** a vértices, arestas e à raiz do diagrama para permitir o uso com [LeanIX bridge](https://github.com/likec4/likec4/tree/main/packages/leanix-bridge) ou ferramentas LeanIX. |

**Ao utilizar o perfil `leanix`:**

- **Vértices e célula raiz:** `bridgeManaged=true`, `likec4Id`, `likec4Kind`, `likec4ViewId`, e, quando fornecido, `likec4ProjectId`. Opcionalmente, `leanixFactSheetType` por tipo de elemento quando `leanixFactSheetTypeByKind` estiver definido (por exemplo, por um gerador personalizado).
- **Arestas:** `likec4RelationId`, `bridgeManaged`.

**CLI:** `likec4 export drawio --profile leanix -o ./diagrams`

**Via API:** Informe `profile: 'leanix'` (e, opcionalmente, `projectId` e `leanixFactSheetTypeByKind`) em `GenerateDrawioOptions`; consulte [API de geradores](#api-de-geradores). Consulte [@likec4/leanix-bridge](https://github.com/likec4/likec4/tree/main/packages/leanix-bridge) para sincronização e mapeamento bidirecional.

### Mapeamento para Draw.io

| LikeC4 | Draw.io |
|--------|---------|
| Visão (ID da visão) | Aba do diagrama (`name` e `id`); título/descrição da visão na célula raiz como `likec4ViewTitle`, `likec4ViewDescription` |
| ID do elemento | mxCell `id` (interno); hierarquia por `parent` |
| Título e descrição do elemento | mxCell `value` (título; descrição em HTML ou no estilo `likec4Description`) |
| Elemento: tecnologia, notas, tags, **navigateTo**, icon | Estilo `likec4Technology`, `likec4Notes`, `likec4Tags`, `likec4NavigateTo`, `likec4Icon` (URI-encoded). **navigateTo** também é registrado como **link** da célula Draw.io, permitindo abrir a aba da visão ao clicar (veja abaixo). |
| Elemento: resumo e links | Estilo `likec4Summary`, `likec4Links` (array JSON) |
| Elemento: notação | Estilo `likec4Notation` |
| Elemento: forma | Estilo `shape` (rectangle, umlActor, cylinder3, document, etc.) |
| Elemento: cor | Estilo `fillColor`, `strokeColor`, `fontColor` (hexadecimal); nome do tema/cor personalizada em `likec4ColorName`; traço em `likec4StrokeColor` para intercâmbio bidirecional |
| Elemento: borda e opacidade | Estilo `strokeWidth`, `likec4Border`, `likec4StrokeWidth` (intercâmbio bidirecional); `opacity` |
| Elemento: tamanho, padding, textSize e posição do ícone | Estilo `likec4Size`, `likec4Padding`, `likec4TextSize`, `likec4IconPosition` |
| Notação da visão | Célula raiz `likec4ViewNotation` (intercâmbio bidirecional) |
| Posição/tamanho do elemento | mxGeometry `x`, `y`, `width`, `height` (do layout; configurável por opções) |
| Dados personalizados de elementos/arestas | mxUserObject `<data key="k">v</data>` (intercâmbio bidirecional) |
| Pontos intermediários da aresta | mxGeometry `relative="0"` com `<Array>` de `<mxPoint>` (quando o modelo da visão contém `points`) |
| Relacionamento: origem, destino e rótulo | Aresta mxCell com `source`, `target` e `value` |
| Relacionamento: descrição, tecnologia, notas e navigateTo | Estilo `likec4Description`, `likec4Technology`, `likec4Notes`, `likec4NavigateTo` |
| Relacionamento: tipo e notação | Estilo `likec4RelationshipKind`, `likec4Notation` |
| Relacionamento: links e metadados | Estilo `likec4Links` (array JSON), `likec4Metadata` (objeto JSON) |
| Relacionamento: ponta/cauda, estilo de linha e cor | Estilo `endArrow`, `startArrow`, `dashed`/`dashPattern`, `strokeColor`; o rótulo usa a configuração do tema `relationships.label` para a cor da fonte |

**Navegação (elementos com visão própria):** Se o elemento tiver **navigateTo** definido (no modelo) com o ID de uma visão, a célula exportada para Draw.io receberá um **link** que abre a aba `likec4-<viewId>`. Ao exportar todas as visões com `--all-in-one`, clicar nesse elemento abrirá a aba que mostra seus detalhes internos. Defina `navigateTo <viewId>` no elemento do modelo LikeC4 para que o exportador adicione automaticamente esse link.

A exportação utiliza o **tema do projeto** (ou o padrão do LikeC4) nas cores dos elementos e relacionamentos. Contêineres (*bounded contexts*) são desenhados **atrás** dos filhos como um retângulo envolvente; os **pontos de conexão** das arestas são derivados do layout para conectar as setas aos lados corretos dos nós.

O **Playground** grava o XML do diagrama sem compactação por padrão, para maximizar a compatibilidade.
A **CLI** utiliza compactação por padrão; use `--uncompressed` para gravá-lo sem compactação.

### O que não é preservado na exportação

- Regras das visões (include/exclude e estilos): somente os nós e arestas resultantes são exportados.
- Desvios de layout e ajustes finos: somente a posição final dos nós é registrada (ou o `layoutOverride` informado).
- Nomes de cores do tema: armazenados em hexadecimal no Draw.io; `likec4ColorName` preserva o nome para intercâmbio bidirecional.

## Reexportação usando blocos de comentários

O exportador pode obter o layout, a cor/largura dos traços dos vértices e os pontos intermediários das arestas a partir de blocos de comentários de intercâmbio bidirecional nos arquivos `.c4`,
de modo que o arquivo `.drawio` gerado corresponda a um diagrama editado anteriormente.
Os blocos são gravados por `parseDrawioToLikeC4` ou manualmente:

| Bloco | Conteúdo |
| ----- | -------- |
| `// <likec4.layout.drawio>` … `// </likec4.layout.drawio>` | JSON com posições e tamanhos dos nós por visão: `{ "<viewId>": { "nodes": { "<fqn>": { "x", "y", "width", "height" } } } }` |
| `// <likec4.strokeColor.vertices>` … `// </likec4.strokeColor.vertices>` | Uma linha `// <fqn>=<hex>` por elemento |
| `// <likec4.strokeWidth.vertices>` … `// </likec4.strokeWidth.vertices>` | Uma linha `// <fqn>=<largura>` por elemento |
| `// <likec4.edge.waypoints>` … `// </likec4.edge.waypoints>` | Uma linha `// <source>\|<target> [[x,y],…]` por aresta; a chave pode terminar com `\|<edgeId>` para arestas paralelas |

- **CLI:** `likec4 export drawio --roundtrip` lê todos os arquivos `.c4` e `.likec4` do workspace e aplica os blocos.
  Com `--all-in-one`, eles são aplicados em cada visão desse arquivo.
- **Playground:** a exportação aplica os blocos encontrados nos arquivos do workspace atual.

### API de geradores

O pacote `@likec4/generators` exporta as funções utilizadas pela CLI e pelo Playground, para ferramentas personalizadas:

```ts
import {
  buildDrawioExportOptionsFromSource,
  generateDrawio,
  generateDrawioMulti,
  parseDrawioRoundtripComments,
  type GenerateDrawioOptions,
} from '@likec4/generators'

// One view, one diagram
const xml = generateDrawio(viewmodel, { compressed: false })

// Several views as tabs of one file, options per view id
const multiXml = generateDrawioMulti(viewmodels, { [viewId]: { profile: 'leanix', projectId } })

// Options from round-trip comment blocks in the .c4 source
const options = buildDrawioExportOptionsFromSource(viewId, c4Source)
```

`viewmodel` é uma visão com layout obtida pela [API do modelo](/pt-br/tooling/model-api/) (por exemplo, `model.view('index')`).
`GenerateDrawioOptions` inclui `layoutOverride` (caixa delimitadora por nó `{ x, y, width, height }`, com a mesma estrutura de `@likec4/core` BBox),
`strokeColorByNodeId`, `strokeWidthByNodeId`, `edgeWaypoints`, `compressed` (`generateDrawio` utiliza compactação, a menos que seja `false`)
e `profile` (`default` ou `leanix`; com `leanix`, opcionalmente `projectId` e `leanixFactSheetTypeByKind`).

## Solução de problemas

**O arquivo .drawio exportado não abre no Draw.io** (por exemplo, erro "Could not add object Array", diagrama em branco ou nenhuma resposta em Abrir arquivo/Importar):

- **Playground:** as exportações são **não compactadas** por padrão, para permitir abrir o arquivo no Draw.io desktop ou em Abrir arquivo/Importar. Atualize a aplicação e exporte novamente.
- **CLI:** utilize **`--uncompressed`** para gravar o XML do diagrama sem compactação: `likec4 export drawio --uncompressed -o ./out`. Isso produz um arquivo maior, que pode ser aberto de modo confiável no Draw.io desktop.
- Se ainda utilizar exportações compactadas, **atualize para a versão mais recente** (versões antigas utilizavam uma estrutura XML inválida para pontos intermediários das arestas): `pnpm update likec4` ou `npm update likec4`, e exporte novamente.

**O diagrama mostra menos elementos do que o esperado:**

- Cada visão exporta **exatamente o que é exibido** nela. Uma visão de nível superior (por exemplo, `view index { include * }`) normalmente exibe apenas **elementos de nível superior** (como Customer e Our SaaS). Elementos aninhados (como Frontend e Backend dentro do sistema) aparecem na **visão do elemento** correspondente (por exemplo, `view saas of saas { include * }`). Para reunir todos os elementos em um arquivo Draw.io, utilize **Exportar todas as visões** (CLI: `--all-in-one`) e abra a aba da visão aninhada, ou selecione essa visão no Playground antes de exportar.
