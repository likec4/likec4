A biblioteca React do LikeC4 permite incorporar diagramas às suas aplicações.
Há várias formas de utilizá-la:

- [Pacote completo](#pacote-completo): componentes de `likec4/react`; você prepara o modelo
- [Componentes gerados](#componentes-gerados): a CLI gera componentes já vinculados ao seu modelo
- [Plugin para Vite](/pt-br/tooling/vite-plugin/): os mesmos componentes a partir de um módulo virtual, atualizados conforme você edita os arquivos-fonte
- [Biblioteca](#biblioteca): `@likec4/diagram` com o seu bundler; você gerencia os estilos

## Pacote completo

Esta é a maneira mais simples de utilizar a biblioteca.  
O diagrama é renderizado no Shadow DOM, com todas as dependências incluídas e estilos gerenciados automaticamente.

### LikeC4ModelProvider

A renderização do diagrama exige uma instância de `LikeC4Model.Layouted`.
Prepare o modelo e envolva o diagrama com o componente `LikeC4ModelProvider`.  
A seguir, algumas maneiras de preparar o modelo:
- Utilizando geração de código pela CLI
- Utilizando arquivos-fonte
- Utilizando o Model Builder

<br />

<Tabs>
  <Tab label='CLI Codegen'>
    Prepare o modelo com a [geração de código](/pt-br/tooling/code-generation/model/):

    ```sh
    likec4 codegen model --outfile ./likec4-model.ts
    ```

    Em seguida:

    ```tsx copy
    import { LikeC4ModelProvider } from 'likec4/react'
    // import model from generated file
    import { likec4model } from './likec4-model.ts'

    function App() {
      return (
        <LikeC4ModelProvider likec4model={likec4model}>
          {/* ... */}
        </LikeC4ModelProvider>
      )
    }
    ```
  </Tab>

  <Tab label='From Sources'>
  A [API do LikeC4](/pt-br/tooling/model-api/#como-usar) analisa os arquivos-fonte e calcula o layout, mas funciona apenas no Node.js.
  Execute-a como uma etapa do build e salve os dados do modelo em um arquivo JSON:

  ```ts copy title="scripts/dump-model.mts"
  import { LikeC4 } from 'likec4'
  import { writeFile } from 'node:fs/promises'

  // or LikeC4.fromSource(`...`) to parse a string
  await using likec4 = await LikeC4.fromWorkspace('./architecture')
  const model = await likec4.layoutedModel()

  await writeFile('./src/likec4-model.json', JSON.stringify(model.$data))
  ```

  Em seguida, crie o modelo a partir desse arquivo na sua aplicação:

  ```tsx copy
  import { LikeC4Model } from 'likec4/model'
  import { LikeC4ModelProvider } from 'likec4/react'
  import data from './likec4-model.json'

  const likec4model = LikeC4Model.fromDump(data)

  function App() {
    return (
      <LikeC4ModelProvider likec4model={likec4model}>
        {/* ... */}
      </LikeC4ModelProvider>
    )
  }
  ```
  </Tab>

  <Tab label='Model Builder'>   
  Você pode preparar o modelo com o [Builder](/pt-br/tooling/model-api/#model-builder) e depois calcular o layout com `layoutLikeC4Model`:
  
  ```tsx copy collapse={8-53}
  import { LikeC4ModelProvider } from 'likec4/react'
  import { Builder } from "likec4/model/builder"
  // O mecanismo de layout é um pacote separado
  import { layoutLikeC4Model } from "@likec4/layouts"

  const computedModel = Builder
    .specification({
      elements: {
        actor: {
          style: {
            shape: 'person',
          },
        },
        system: {},
        component: {},
      },
      relationships: {
        likes: {},
      },
      tags: ['tag1', 'tag2', 'tag1'],
    })
    .model(({ actor, system, component, relTo, rel }, _) =>
      _(
        actor('alice'),
        actor('bob'),
        rel('alice', 'bob', {
          tags: ['tag1'], // you get code completion for tags
          kind: 'likes',  // code completion for kind
        }),
        system('cloud', { tags: ['tag1', 'tag2'] }).with(
          component('backend').with(
            component('api'),
            component('db'),
            // code completion for relationships
            rel('cloud.backend.api', 'cloud.backend.db')
          ),
          component('frontend').with(
            relTo('cloud.backend.api')
          ),
        ),
      )
    )    
    .views(({ view, viewOf, $include, $style }, _) =>
      _(
        view('index', 'Index').with(
          $include('cloud.*'),
        ),
        viewOf('ui', 'cloud.ui').with(
          $include('* -> cloud.**'),
          $style('cloud.ui', { color: 'red' }),
        ),
      )
    )
    .toLikeC4Model()

  // The Builder returns a computed model. To render it, you need to lay it out
  const likec4model = await layoutLikeC4Model(computedModel)

  function App() {
    return (
      <LikeC4ModelProvider likec4model={likec4model}>
        {/* ... */}
      </LikeC4ModelProvider>
    )
  }      
  ```
  </Tab>
</Tabs>

:::tip
O pacote `likec4` é tudo de que você precisa para estes exemplos:
- `likec4/react`: componentes e hooks React
- `likec4/model`: a API do modelo e os tipos (o mesmo que `@likec4/core/model` e `@likec4/core/types`)
- `likec4/model/builder`: o construtor de modelos (o mesmo que `@likec4/core/builder`)
:::

Nos exemplos a seguir, `likec4model` é o modelo preparado de uma das formas acima.

### LikeC4View

```tsx
import { LikeC4View, LikeC4ModelProvider } from 'likec4/react'

function App() {
  return (
    <LikeC4ModelProvider likec4model={likec4model}>
      <LikeC4View viewId="index" />
      {/* Possible to have multiple views */}
      <LikeC4View viewId="ui" browser={false} />
    </LikeC4ModelProvider>
  )
}
```

Um clique na visão a abre em uma janela de navegação, onde é possível explorar o modelo.

| Propriedade     | Descrição |
| --------------- | --------- |
| `viewId`        | Visão a ser exibida |
| `layoutType`    | `manual` (padrão) utiliza o layout manual, se a visão tiver um; `auto` o ignora |
| `browser`       | Abre a janela de navegação ao clicar (padrão `true`) |
| `pannable`      | Habilita o deslocamento (padrão `false`) |
| `zoomable`      | Habilita o zoom (padrão `false`) |
| `colorScheme`   | `light` ou `dark`; por padrão, segue as preferências do sistema |
| `injectFontCss` | Injeta CSS com a fonte <a href='https://fontsource.org/fonts/ibm-plex-sans' target='_blank'>IBM Plex Sans Variable</a> pela CDN (padrão `true`).<br/>Defina como `false` para carregar a fonte por conta própria |
| `where`         | Exibe apenas alguns elementos e relacionamentos; consulte [Filtro](#filtro) |
| `renderIcon`    | Renderiza os ícones dos elementos; consulte [Ícones](#ícones) |

Consulte [LikeC4ViewProps](https://github.com/likec4/likec4/blob/main/packages/diagram/src/LikeC4View.tsx) para conhecer todas as propriedades.

:::caution
`LikeC4View` pode não realizar a hidratação corretamente quando renderizado no servidor; prefira a renderização no cliente.
:::

### ReactLikeC4

`LikeC4View` renderiza visões do modelo e permite explorá-las em uma janela de navegação.
Esse componente atende à maioria dos cenários. Caso precise de mais controle e queira reagir aos eventos, utilize `ReactLikeC4`:

```tsx
import { ReactLikeC4, LikeC4ModelProvider } from 'likec4/react'
import { useState } from 'react'

function App() {
  const [viewId, setViewId] = useState('index')
  return (
    <LikeC4ModelProvider likec4model={likec4model}>
      <ReactLikeC4
        viewId={viewId}
        pannable
        zoomable={false}
        keepAspectRatio
        showNavigationButtons
        enableDynamicViewWalkthrough={false}
        enableElementDetails
        enableRelationshipDetails
        onNavigateTo={setViewId}
        onNodeClick={(node) => console.log('clicked', node.id)}
      />
    </LikeC4ModelProvider>
  )
}
```

Consulte [LikeC4Diagram.props.ts](https://github.com/likec4/likec4/blob/main/packages/diagram/src/LikeC4Diagram.props.ts) para conhecer as propriedades e os manipuladores de eventos disponíveis.

### Filtro

`where` utiliza o mesmo conceito de [predicado de visão](/pt-br/dsl/views/predicates/#filtro), mas é aplicado dinamicamente e permite exibir ou ocultar elementos conforme o contexto.
`LikeC4View` e `ReactLikeC4` aceitam essa propriedade:

```tsx
// Keeps elements and relationships where:
// - tag is not 'legacy'
// - and
// - tag is 'v1' or 'v2'
<LikeC4View
  viewId="index"
  where={{
    and: [
      { tag: { neq: 'legacy' } },
      {
        or: [
          { tag: { eq: 'v1' } },
          { tag: { eq: 'v2' } }
        ]
      }
    ]
  }}
/>
```

O layout permanece inalterado, ou seja, os elementos não são reorganizados.  
Atenção: `where` é aplicado tanto a elementos quanto a relacionamentos.


### Ícones

Se você utilizar os ícones integrados, instale [`@likec4/icons`](https://www.npmjs.com/package/%40likec4%2Ficons):

```tsx
import type { ElementIconRenderer } from 'likec4/react'
import { LikeC4ModelProvider, LikeC4View, ReactLikeC4 } from 'likec4/react'
import { lazy, Suspense } from 'react'

// Better to lazy load icons, bundle is quite large at the moment
const Icon = lazy(async () => {
  const { IconRenderer } = await import('@likec4/icons/all')
  return { default: IconRenderer }
})

const IconRenderer: ElementIconRenderer = (props) => (
  <Suspense>
    <Icon {...props} />
  </Suspense>
)

function App() {
  return (
    <LikeC4ModelProvider likec4model={likec4model}>
      <LikeC4View
        viewId="index"
        renderIcon={IconRenderer}
      />
      {/* Same for ReactLikeC4 */}
      <ReactLikeC4
        viewId="ui"
        renderIcon={IconRenderer}
      />
    </LikeC4ModelProvider>
  )
}
```

## Componentes gerados

A CLI gera um módulo JavaScript com `LikeC4View` e `ReactLikeC4` já vinculados ao seu modelo:
eles dispensam o `LikeC4ModelProvider`, os ícones vêm incluídos e `viewId` é tipado com os IDs das suas visões.

<Aside type='tip' title="Plugin para Vite">
O [plugin para Vite](/pt-br/tooling/vite-plugin/) fornece os mesmos componentes a partir de um módulo virtual e os atualiza conforme você edita os arquivos-fonte. Consulte o [exemplo com Next.js](/pt-br/tooling/vite-plugin/#com-nextjs).
</Aside>

### Gerar

<PackageManagers
   type="dlx"
   pkg="likec4"
   args="gen react -o ./src/likec4.generated.js"
   pkgManagers={['npm', 'pnpm', 'yarn', 'bun']}
   frame="none"
   />

<br />

`generate` e `codegen` são aliases de `gen`:

```sh frame="none"
likec4 generate react -o ./src/likec4.generated.js
likec4 codegen react -o ./src/likec4.generated.js
```

O comando grava o módulo e, ao lado dele, o arquivo de declarações de tipos (`likec4.generated.js` e `likec4.generated.d.ts`).

| Opção | Descrição |
| ----- | --------- |
| `[path]` | Diretório com os arquivos-fonte do LikeC4 (padrão: diretório atual) |
| `-o`, `--outfile` | Arquivo de saída, deve ser `.js`, `.mjs` ou `.jsx` (padrão: `likec4-views.js` no workspace) |
| `-p`, `--project` | Projeto a ser gerado, por nome ou caminho, em um workspace com [vários projetos](/pt-br/config/multi-projects/) |
| `--customization` | Inclui a [personalização da UI](/tooling/customization/) nos componentes (experimental) |
| `--app-config` | Caminho para a [configuração da aplicação](/tooling/app-config/); `--no-app-config` para ignorá-la |
| `--use-dot` | Utiliza os binários locais do Graphviz (`dot` no `PATH`) em vez do WASM incluído |
| `--use-core-package` | Importa os tipos de `@likec4/core` em vez de `likec4` no `.d.ts` |

Execute `likec4 gen react --help` para conhecer todas as opções.

### Exportações

| Exportação | Descrição |
| ---------- | --------- |
| `LikeC4View` | [LikeC4View](#likec4view) com o modelo e os ícones |
| `ReactLikeC4` | [ReactLikeC4](#reactlikec4) com o modelo e os ícones |
| `LikeC4ModelProvider` | Fornece o modelo aos componentes e [hooks](#hooks) de `likec4/react`; recebe apenas `children` |
| `likec4model` | O modelo, instância de `LikeC4Model` |
| `useLikeC4Model()` | Retorna o modelo; funciona fora do `LikeC4ModelProvider` |
| `useLikeC4View(viewId)` | Retorna a visão com layout |
| `isLikeC4ViewId(value)` | Verifica se o valor é o ID de uma visão |
| `RenderIcon` | Renderiza os ícones incluídos; passe-o para `renderIcon` |
| `LikeC4ViewProps`, `ReactLikeC4Props` | Tipos das propriedades dos componentes |
| `$ViewId`, `$ElementId`, `$Tag`, … | Tipos dos IDs e dos tipos do modelo |

### Utilização

Os componentes gerados aceitam as mesmas propriedades que os do [pacote completo](#pacote-completo), exceto o modelo:

```tsx
import { LikeC4View } from './likec4.generated'

const App = () => {
  return <LikeC4View viewId="index" />
}
```

```tsx
import { ReactLikeC4, type $ViewId } from './likec4.generated'
import { useState } from 'react'

const App = () => {
  const [viewId, setViewId] = useState<$ViewId>('index')
  return (
    <ReactLikeC4
      viewId={viewId}
      pannable
      onNavigateTo={setViewId}
    />
  )
}
```

Para utilizar os componentes de `likec4/react` com o modelo gerado, passe `likec4model` e `RenderIcon`:

```tsx
import { ReactLikeC4, LikeC4ModelProvider } from 'likec4/react'
import { RenderIcon, likec4model } from './likec4.generated'

const App = () => {
  return (
    <LikeC4ModelProvider likec4model={likec4model}>
      <ReactLikeC4
        viewId="index"
        renderIcon={RenderIcon}
        onEdgeClick={(edge) => console.log('clicked', edge.id)}
      />
    </LikeC4ModelProvider>
  )
}
```

## Biblioteca

Se quiser utilizar o pacote como biblioteca com seu bundler, será necessário gerenciar o CSS.  
Para isso, adicione [`@likec4/core`](https://www.npmjs.com/package/%40likec4%2Fcore) e [`@likec4/diagram`](https://www.npmjs.com/package/%40likec4%2Fdiagram) em vez de `likec4`:

<PackageManagers
    pkg="@likec4/core @likec4/diagram"
    pkgManagers={['npm', 'pnpm', 'yarn', 'bun']}
    frame="none"
  />
<br />

A biblioteca utiliza [Mantine](https://mantine.dev). Se sua aplicação já utilizar `MantineProvider`, o diagrama LikeC4 aproveitará esse provedor.
Caso contrário, o diagrama será envolvido automaticamente por `MantineProvider`.  
Mesmo que sua aplicação não utilize Mantine diretamente, os estilos da biblioteca são necessários para os diagramas (e o Mantine permite eliminar código não utilizado via tree-shaking).

Confira as opções:

### Com estilos incluídos

1. Importe todos os estilos

   ```css
   @import '@likec4/diagram/styles.css'
   ```

   Isso inclui todos os estilos, inclusive os do [Mantine](https://mantine.dev).

2. Se você já utiliza Mantine

   ```css
   @layer reset, base, mantine, xyflow, tokens, recipes, utilities;
   @import "@mantine/core/styles.layer.css";
   @import "@likec4/diagram/styles-min.css";
   ```

   :::caution
   A ordem das camadas é importante: a camada `mantine` deve vir antes de `xyflow`, e `xyflow` antes de `tokens`.
   :::

3. Fonte.\
   Por padrão, `LikeC4Diagram` utiliza a fonte [`IBM Plex Sans Variable`](https://fontsource.org/fonts/ibm-plex-sans).\
   Você pode incluí-la no bundle, importá-la pelo [fontsource](https://fontsource.org/fonts/ibm-plex-sans), utilizar outra CDN ou usar:

   ```css
   @import '@likec4/diagram/styles-font.css'
   ```

   Para utilizar outra fonte, defina a variável `--likec4-app-font`.
   O layout é calculado com as métricas da IBM Plex Sans; com outra fonte, os rótulos podem se ajustar de outra forma.

   ```css
   :root {
     --likec4-app-font: 'Inter Variable', sans-serif;
   }
   ```

### Com PandaCSS

Consulte a [documentação do PandaCSS](https://panda-css.com) para obter as instruções completas de configuração.  
O LikeC4 disponibiliza um preset.


```css

@import "@likec4/diagram/styles-xyflow.css";

```

### Renderizar uma visão

Importe os componentes de `@likec4/diagram`.
`LikeC4Diagram` recebe a visão a ser renderizada (`DiagramView`) e as mesmas propriedades de [ReactLikeC4](#reactlikec4):

```tsx
import { LikeC4Diagram, LikeC4ModelProvider, useLikeC4ViewModel } from '@likec4/diagram'

function LikeC4View({ viewId }: { viewId: string }) {
  const view = useLikeC4ViewModel(viewId)
  return (
    <LikeC4Diagram
      view={view.$view}
      pannable
      zoomable={false}
      showNavigationButtons
      enableDynamicViewWalkthrough={false}
      enableElementDetails
      enableRelationshipDetails
    />
  )
}

function App() {
  return (
    <LikeC4ModelProvider likec4model={likec4model}>
      <LikeC4View viewId="index" />
    </LikeC4ModelProvider>
  )
}
```

## Atalhos de teclado

Diagramas em foco oferecem atalhos de teclado para zoom. Clique em um diagrama ou acesse-o pela tecla Tab; enquanto ele estiver em foco,
esses atalhos controlam o zoom do diagrama, e não o zoom da página do navegador. Retire o foco do diagrama com Tab para utilizar o zoom do navegador.

| Atalho | Ação |
| --- | --- |
| `Ctrl`/`Cmd` + `+` ou `=` | Ampliar |
| `Ctrl`/`Cmd` + `-` ou `_` | Reduzir |
| `Ctrl`/`Cmd` + `0` | Redefinir a área de visualização |

## Personalização

### Slots de UI (experimental)

:::caution[Experimental]
Substitua ou envolva partes da UI (`LikeC4Diagram`, logos, …) com `CustomizationProvider`.
Esta API pode mudar; os nomes dos slots podem crescer, mas trate os helpers como experimentais por enquanto.
:::

Há duas camadas de personalização:

1. **Slots de UI** — substituir ou envolver componentes registrados da shell
2. **Renderizadores de nós** — personalizar como os nós são desenhados (veja abaixo)

```tsx
import {
  CustomizationProvider,
  defineCustomComponents,
  LikeC4ModelProvider,
  LikeC4View,
} from 'likec4/react'

const components = defineCustomComponents(({ wrap }) => ({
  LogoSvg: (props) => <svg {...props}><text>Brand</text></svg>,
  LikeC4View: wrap(({ Original, ...props }) => (
    <Original {...props} pannable={false} />
  )),
}))

function App() {
  return (
    <CustomizationProvider components={components}>
      <LikeC4ModelProvider likec4model={likec4model}>
        <LikeC4View viewId="index" />
      </LikeC4ModelProvider>
    </CustomizationProvider>
  )
}
```

- **replace** — passe um componente com as mesmas props do slot
- **wrap** — use `wrap`; o componente recebe `{ Original, ...props }`

Coloque `CustomizationProvider` acima da árvore do diagrama. A ordem em relação a `LikeC4ModelProvider` não importa. Prefira uma constante `components` no escopo do módulo para manter os overrides amigáveis ao HMR.

Com `@likec4/diagram`, importe os mesmos helpers de `@likec4/diagram/custom`.

Consulte [Personalização da UI](/tooling/customization/) para ver a lista de slots e como aplicar os overrides à aplicação LikeC4 (CLI, plugin para Vite) a partir de um arquivo.

### Filhos e portais

É possível renderizar qualquer componente dentro de `LikeC4Diagram`\
(ou de `LikeC4View`/`ReactLikeC4`, caso utilize o pacote completo):

```tsx
import { LikeC4Diagram, useLikeC4ViewModel } from '@likec4/diagram'
import { Panel, ViewportPortal } from '@xyflow/react'

function Diagram({ viewId }: { viewId: string }) {
  const view = useLikeC4ViewModel(viewId)
  return (
    <LikeC4Diagram view={view.$view}>
      <YourComponent />

      {/* You can use components from xyflow  */}
      <Panel position="top-center">
        <p>Your component as a panel</p>
        <a href="https://reactflow.dev/examples">Check examples</a>
      </Panel>

      <ViewportPortal>
        <div
          style={{
            transform: 'translate(100px, 100px)',
            position: 'absolute',
          }}>
          This div is positioned at [100, 100] on the diagram canvas
        </div>
      </ViewportPortal>
    </LikeC4Diagram>
  )
}
```

### Renderizadores personalizados de nós

`LikeC4Diagram` permite utilizar renderizadores personalizados para os nós.\
Crie renderizadores personalizados usando os componentes básicos de `likec4/react`\
(ou de `@likec4/diagram/custom`, caso utilize a biblioteca).\
Consulte [customNodes.tsx](https://github.com/likec4/likec4/blob/main/packages/diagram/src/custom/customNodes.tsx) para ver exemplos.

```tsx
import { LikeC4Diagram, useLikeC4ViewModel } from '@likec4/diagram'
import {
  ElementActions,
  elementNode,
  ElementNodeContainer,
  ElementShape,
  ElementData,
} from '@likec4/diagram/custom'
import { IconPlus } from '@tabler/icons-react'

const customNodes = {
  element: elementNode(({ nodeProps, nodeModel }) => (
```
