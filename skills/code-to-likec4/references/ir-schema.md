# IR schema (JSON envelope `{ "elements": [...], "proposals": [...] }`)

Default granularity: file = parent element; module classes, top-level functions, and route handlers = nested components. Symbol-free files fall back to file = component.

File-level + routes (for large repos): `scan --symbol-kinds route` (or `--no-symbols` for strict file-only), `auto-label --keep-symbols route` (shorthand `--drop-symbols`), `emit --drop-symbols`. Routes always survive pruning; helper functions/variables/classes are dropped and their `calls` fold away with them (file-level `imports` edges are unaffected).

| Field        | Type               | Required            | Notes                                                                                                                   |
| ------------ | ------------------ | ------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| `fqn`        | string             | emit fills if empty | `<system>.<area>.<file>[.<symbol>]`, segments match `[A-Za-z_][A-Za-z0-9_-]*`                                           |
| `kind`       | string             | emit defaults       | `person, system, container, component, database` (parents with children default to `container`)                         |
| `title`      | string             | yes                 | human label                                                                                                             |
| `file`       | string             | yes                 | repo-relative path                                                                                                      |
| `lang`       | `ts`\|`py`         | yes                 | scanner source                                                                                                          |
| `symbol`     | string\|null       | no                  | class/function/route name (`null` = file parent)                                                                        |
| `symbolKind` | string\|null       | no                  | `class`, `function`, `variable`, `route`                                                                                |
| `line`       | number             | no                  | 1-based evidence line, rendered as `// evidence: file:line`                                                             |
| `parent`     | string\|null       | no                  | scanner: parent file path; labeled: parent FQN also accepted                                                            |
| `route`      | string\|null       | no                  | e.g. `POST /predict`, rendered as `description`                                                                         |
| `imports`    | (string\|object)[] | yes                 | string = default `imports` kind; object `{to, kind, label, line}`                                                       |
| `calls`      | (string\|object)[] | yes                 | bare scanner names resolve to sibling symbols as `inproc`; objects pass through                                         |
| `extends`    | string[]           | yes                 | base class names                                                                                                        |
| `technology` | string             | no                  | e.g. `FastAPI`                                                                                                          |
| `tags`       | string[]           | yes                 | always contains `autogenerated` (IR metadata only — `emit.mjs` does not render it; provenance is a file header comment) |

Relationship kinds (fixed set): `http, kafka, s3, promql, inproc, calls, imports, inherits`. Rendered `a -[kind]-> b "label"` (plain `->` for unlabeled `imports`).

`proposals[]` (infra/actor candidates — never auto-added, LLM promotes/drops):

```json
{
  "kind": "container",
  "title": "Kafka Message Broker",
  "technology": "Apache Kafka",
  "source": "infra/kafka.yaml",
  "reason": "k8s Deployment kafka"
}
```

Sources: k8s `kind`/`metadata.name`/`image` (line-regex, no YAML dep), prometheus `job_name` entries, compose services (skips `-data` volumes), client-lib signals (`aiokafka`, `mlflow`, `prometheus_client`, `boto3`, `redis`, ...).

Labeled example (child):

```json
{
  "fqn": "demo.serving.servingApp.predict",
  "kind": "component",
  "title": "Predict",
  "file": "serving/app.py",
  "lang": "py",
  "symbol": "predict",
  "line": 212,
  "parent": "demo.serving.servingApp",
  "route": "POST /predict",
  "imports": [],
  "calls": [{ "to": "demo.serving.servingApp.decode_image", "kind": "inproc" }],
  "extends": [],
  "technology": "FastAPI",
  "tags": ["autogenerated"]
}
```

Rules: identifier, FQN, and nesting rules follow the `likec4-dsl` skill (`references/identifier-validity.md`, `references/model.md`). FQNs must be unique project-wide; use full FQNs for cross-file references. The emitter fails on duplicate explicit FQNs, dedupes generated ones, and warns when output exceeds ~200 elements (symbols included).
