# Documentation

Canonical task guidance referenced by root AGENTS.md. Read it before changing `apps/docs` or `skills/likec4-dsl`.

## Documentation structure

The site is Astro Starlight in `apps/docs`; pages live in `apps/docs/src/content/docs/`.

- Getting started: `tutorial.mdx` and the editors page.
- Language (`dsl/`): the DSL only — model, relationships, views, deployment, styling, diffs.
- Project setup (`config/`): project config files, multi-projects, and the overview of all config files.
- Tooling (`tooling/`): CLI, CI, embedding (Vite plugin, React, web components, app config, UI customization),
  the model API and code generation, AI tools, community.
- Guides (`guides/`): task walkthroughs — publish, validate in CI, embed into a website.
- Showcases (`showcases/`).

Rules:

- One canonical page per topic. Other pages link to it; never copy its content or its option tables.
- Reference pages say what exists. Guides walk through one task end to end and link the reference for flags and options.
- CLI flags, app config, React/Vite and UI behavior do not belong in Language pages.
- Every page starts with a sentence that says what it covers. Use sentence-case headings.
- Do not publish TODOs, "coming soon", or position words like "next section" or "above" that break when pages move.

## Verify against the code

Every statement about syntax, options, flags, defaults or APIs must match the source. If the code does not confirm it, leave it out.

| Topic                                  | Source of truth                                                              |
| -------------------------------------- | ---------------------------------------------------------------------------- |
| DSL syntax                             | `packages/language-server/src/like-c4.langium`                               |
| DSL restrictions and error messages    | `packages/language-server/src/validation/`                                   |
| CLI commands, flags, aliases, defaults | yargs definitions in `packages/likec4/src/cli`                               |
| Project config                         | `packages/config/src/schema.ts`, `packages/config/src/filenames.ts`          |
| App config                             | `packages/likec4/src/app-config`                                             |
| Vite plugin options, virtual modules   | `packages/vite-plugin/src`                                                   |
| Model API                              | `packages/core/src/model`, `packages/language-services/src/common/LikeC4.ts` |
| Package exports                        | `exports` in `packages/likec4/package.json`                                  |

Snippets must be valid: imports present, every name defined, ids that exist in the snippet's model, async calls awaited.
For non-trivial TypeScript, typecheck the snippet against the sources in a temporary file and delete it afterwards.

Keep `skills/likec4-dsl/` (`SKILL.md` and `references/`) consistent with the docs when DSL behavior or status changes,
for example when a feature stops being experimental.

## Translations

`apps/docs/src/content/docs/pt-br/` mirrors the English pages.

- Apply every change to the pt-br page too, in Portuguese. Code and code comments stay in English.
- pt-br headings produce Portuguese anchors; check the heading before linking to `#anchor` on a pt-br page.
- Link to a page that has no pt-br translation by its English URL, without the `/pt-br/` prefix.
  `starlight-links-validator` rejects links to fallback pages.

## Moving, renaming and deleting pages

- Add a redirect in `apps/docs/astro.config.mjs` for every old URL, both English and pt-br.
- Find and update inbound links in `apps/docs/src` (including `.astro` components), `packages/*/README.md`,
  `skills/`, and URLs printed by the CLI in `packages/likec4/src/cli`. Changing a CLI string needs a changeset.
- Relative image paths (`../../assets/...`) break when a page moves to another folder depth.

## Sidebar

- `dsl/`, `config/` and `guides/` are autogenerated. Give every page a unique `sidebar.order`:
  a folder sorts by the lowest order among its pages, and ties make the order arbitrary.
- Tooling is an explicit list in `apps/docs/astro.config.mjs`. Add a new Tooling page there, or it will not show up.
- `autogenerate.directory` is case-sensitive (`tooling/Community`).

## Check before committing

- `pnpm turbo run build --filter=@likec4/docs-astro` must pass. It builds the packages the docs depend on,
  and `starlight-links-validator` fails the build on broken links and anchors.
- In a fresh worktree run `pnpm install` first.
- Docs-only changes do not need a changeset.
